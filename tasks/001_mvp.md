# Plan: `akf init` MVP

## Context

Today, working inside this repo (and other projects) means Claude Code stops every few turns to ask
permission for Bash commands, WebFetch domains, etc. The architecture doc already settled on the
eventual model: run Claude inside an Apple-`container` micro-VM with
`--dangerously-skip-permissions`, because **the VM is the sandbox**. The prompts go away because the
blast radius is contained.

The MVP is the smallest slice that delivers that: a command, `akf init`, that **augments an existing
project folder** with the sandbox scaffolding needed to boot Claude inside an Apple container. It
does not replace files, does not scaffold a greenfield project, and does not try to support every
workflow — it just makes "let Claude loose in this repo" a one-command setup. The dogfood target is
this repo itself.

The target shape is the "full" sandbox layout described in the architecture doc (minus any
project-specific tooling): `.devcontainer/` for the image, root `start.sh` + `build.sh` for launch.
We do **not** touch `.claude/settings.local.json` — see the Approach section for why.

Chrome CDP proxy is deferred to v0.2. Only the scaffolder machinery (`bin/create.mjs`, root
`package.json`, root `README.md`) gets reworked — the `template/` contents are the authoritative
source for the files we embed.

---

## Approach

Ship `akf` as a **Deno CLI compiled to a single-file binary** from day one. Rationale:

- Matches the architecture decision already on record; no throwaway bash intermediate to port later.
- `deno compile --include templates/` produces a self-contained macOS arm64 binary with the scaffold
  files baked in. Homebrew formula later is just "download the binary and symlink" — no runtime dep
  on `deno`, `node`, or `bash`.
- Real types, real tests, real linting from the start. Keeps us honest as subcommands accrete
  (`run`, `doctor`, etc.).
- During development, `deno task init` runs straight from source with full `--allow-*` flags; we
  only compile when cutting a release.

The command is `akf init`, run from the repo root. It is **idempotent** and **non-destructive**:
never overwrites a file that already exists, appends marker-delimited blocks to text files
(`.gitignore`, `CLAUDE.md`), and prints a short summary of what it touched.

### Repo layout after rework

```

├── src/

│   └── lib/

│       └── markers.ts        # gitignore + markdown block markers
├── templates/                # authoritative scaffold content, plain files

│   ├── start.sh
│   ├── build.sh
│   ├── CLAUDE.block.md       # the marker-delimited block we append
│   └── gitignore.block       # the marker-delimited block we append
├── assets/
```

`templates/` replaces the old `template/` directory. Files are embedded into the compiled binary via
`deno compile --include ./templates`. During dev, `init.ts` reads them relative to `import.meta.url`
so iteration is fast.

## What `akf init` does

Run in CWD. No args for MVP.

1. **Preflight (soft):** check `container` CLI is on PATH; if not, print a warning (don't fail —
   files are still valid for devcontainer use).
2. **Write `.devcontainer/Dockerfile`** if missing. Generic version (no per-project extras); keep it
   to: Debian slim + git, curl, jq, rg, fd-find, tree, vim, gh, Claude Code installed as `node`
   user. Based on `template/Dockerfile` but under `.devcontainer/` so VSCode Dev Containers pick it
   up for free.
3. **Write `.devcontainer/devcontainer.json`** if missing. Generic name
   (`${localWorkspaceFolderBasename}`), same mount pattern as the reference layout.
4. **Write `start.sh`** if missing. Based on `template/start.sh` — mounts `/workspace`,
   `$HOME/.claude`, `$HOME/Downloads` (RO). Runs `claude --dangerously-skip-permissions`. Mark
   executable.
5. **Write `build.sh`** if missing. Based on the Docker→local registry→Apple container workaround
   (the DNS bug is still live in `container` v0.9). Mark executable.
6. **Append to `.gitignore`** if our marker block isn't present. Marker: `# >>> akf >>>` /
   `# <<< akf <<<`. Adds `.akf/` and container state dirs, nothing controversial.
7. **Append to `CLAUDE.md`** if our marker block isn't present (create the file if missing). The
   block documents: that the repo is meant to run in an Apple container, how to launch (`./build.sh`
   once, then `./start.sh`), and the `--dangerously-skip-permissions` reasoning.
8. **Print a summary:** created vs appended vs skipped, and the next two commands to run
   (`./build.sh` then `./start.sh`).

**We do NOT touch `.claude/settings.local.json`.** The sandbox model launches Claude with
`--dangerously-skip-permissions` inside the container, which bypasses the permission check entirely
— so merging an allowlist into the project's settings file has no effect on the prompts users are
trying to escape. Leaving the file alone keeps the user's existing config intact and avoids writing
dead config.

Re-running `akf init` should be a no-op (or only emit "skipped, already present" lines). This is the
idempotency contract.

### Merge semantics details

- **`.gitignore` / `CLAUDE.md`**: marker-delimited block (`# >>> akf >>>` / `# <<< akf <<<` for
  gitignore, `<!-- akf:start -->` / `<!-- akf:end -->` for markdown). Presence of the start marker =
  already installed, skip. This lets users hand-edit outside the block without us clobbering them,
  and lets a future `akf update` rewrite just the block.
- **Files we own wholesale** (`Dockerfile`, `devcontainer.json`, `start.sh`, `build.sh`): if
  missing, write; if present, skip and tell the user. No three-way merge. If they want to
  re-generate they delete and re-run.

## Critical files to modify or create

**New (Deno source):**

- `deno.json` — tasks (`dev`, `test`, `fmt`, `lint`, `compile`), lint/fmt config, `imports` map.
  Compile task: `deno compile -A --include ./templates --output dist/akf src/main.ts`.
- `src/main.ts` — CLI entry. Uses `@std/cli` `parseArgs` for subcommand dispatch; MVP dispatches
  `init` only, prints usage for anything else.
- `src/commands/init.ts` — the `init` command: preflight, iterate over scaffold files, apply
  append-block logic, print summary.
- `src/lib/fs.ts` — helpers: `writeIfMissing(path, contents, mode?)`,
  `appendBlockIfAbsent(path, startMarker, endMarker, block)`. Both return a status for the summary.
- `src/lib/markers.ts` — constants for the two marker pairs.

**New (scaffold content, read at runtime from the bundled assets):**

- `templates/.devcontainer/Dockerfile` — derived from current `template/Dockerfile` (generic, no
  per-project extras).
- `templates/.devcontainer/devcontainer.json` — same shape as the reference layout, with name set to
  `${localWorkspaceFolderBasename}`, `postCreateCommand` dropped.
- `templates/start.sh` — current `template/start.sh` verbatim.
- `templates/build.sh` — the Docker→local registry→Apple container workaround for the DNS bug.
- `templates/CLAUDE.block.md` — the `<!-- akf:start -->` … `<!-- akf:end -->` block explaining
  sandbox usage.
- `templates/gitignore.block` — the `# >>> akf >>>` … `# <<< akf <<<` block.

**Rewritten:**

- `README.md` — replace create-claude-in-an-apple framing with `akf` usage: install, `akf init`,
  what it does, then `./build.sh` + `./start.sh`.

**Deleted (rework cleanup, per CLAUDE.md):**

- `bin/create.mjs`
- `package.json`
- `template/` (content migrates to `templates/` and `assets/chrome-bridge/`).

**Kept untouched:**

- `CLAUDE.md`, `POSITIONING.md`, `ARCHITECTURE_EXPLORATION.md`.

**Moved (not in MVP code path, reserved for v0.2):**

- `template/scripts/launch-chrome-debug.sh` → `assets/chrome-bridge/launch-chrome-debug.sh`.
- `template/.mcp.json` → `assets/chrome-bridge/.mcp.json`.

### Content sources

- `.devcontainer/Dockerfile` → derived from `template/Dockerfile` with `WORKDIR /workspace` and
  user-switch pattern preserved. Generic — no per-project tooling baked in.
- `.devcontainer/devcontainer.json` → based on the reference layout's `devcontainer.json` with name
  switched to `${localWorkspaceFolderBasename}` and `postCreateCommand` dropped.
- `start.sh` → `template/start.sh` verbatim.
- `build.sh` → encodes the Docker→local registry→Apple-container workaround that `template/` is
  missing.
- `.gitignore` block → `.akf/` plus any container state dirs we end up needing; nothing else
  (dev-standard ignores like `.env` belong to the user's own gitignore, not ours).
- `CLAUDE.md` block → short sandbox section: what it is, how to launch, why permission prompts go
  away.

## Out of scope (deferred to later)

- Chrome CDP proxy / Playwright MCP wiring (v0.2). Keep the scripts in `assets/chrome-bridge/`.
- `akf run` ephemeral mode, `akf doctor`, `akf update`, `akf destroy`.
- `.claude` exposure tiers (full/selective/minimal) — MVP mounts all of `~/.claude` ("full"
  exposure).
- Homebrew formula.
- Cross-compile beyond macOS arm64. (`deno compile` can target more later.)
- Image building or container launch from inside `akf init`. User still runs `./build.sh` and
  `./start.sh` manually. Keeps the MVP to file I/O only.
- Prompting before overwrites, interactive mode, flags like `--force`.

## Verification

Two loops: a fast dev loop from source, then a compiled-binary dogfood against this repo.

**Dev loop (from source):**

1. `deno task test` — unit tests for `writeIfMissing` and `appendBlockIfAbsent` (tmpdir-based,
   covers: file absent, file present without marker, file present with marker, marker present but
   block drifted).
2. `deno task dev init` in a tmp scratch dir — smoke test that scaffold files land.

**Compiled dogfood:**

1. `deno task compile` produces `dist/akf`.
2. Copy this repo to a scratch path. Run `./dist/akf init` from its root.
3. Confirm:
   - `.devcontainer/Dockerfile` and `.devcontainer/devcontainer.json` created.
   - `start.sh` and `build.sh` created and executable (`test -x`).
   - `.claude/settings.local.json` is **unchanged** (pre-existing `Bash(xargs cat:*)` entry is the
     only thing in it).
   - `.gitignore` has our marker block; pre-existing lines are untouched and not duplicated inside
     the block.
   - `CLAUDE.md` has the sandbox section appended between markers; existing "Apfelkäfig / Status /
     Decisions made" content intact above it.
4. Re-run `./dist/akf init`. Every step reports "skipped (already present)". No file mtimes change.
5. Run `./build.sh` then `./start.sh`. Inside the container: `claude
   --version` works,
   `/workspace` shows this repo, `~/.claude` shows the host's Claude config. Quit.
6. In a blank scratch folder (`mkdir /tmp/akf-blank && cd $_ && touch
   README.md`), run
   `akf init`. Same end state, no errors on missing `CLAUDE.md` / `.gitignore`.
